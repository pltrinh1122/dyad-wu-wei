# WHY: Decoupled Ledger Architecture for Path Containers

## Current Fragility
The `Path` container architecture has repeatedly seized the SPAO engine (causing "Zombie Paths") because of three structural flaws:
1. **The Meta-Index Stagnation:** The engine relies on the Meta-Index checkboxes (`[ ]` vs `[x]`) to determine if a Path is exhausted. However, no mechanism exists to check these boxes when a child node completes.
2. **The NBA Masking Patch:** Instead of fixing the topological sorting, PR #2184 simply hid `Path:` issues from `global_backlog.yml`. This prevented the engine from locking onto containers but orphaned the containers entirely.
3. **The Garbage Collection Failure:** Because the Meta-Index was never checked off, `nba.evaluate()` always assumed the Path had pending work, preventing `bin/node reflect` from ever reaching the `nba_result["type"] == "path_switching"` branch that was supposed to autonomously close the parent Path.

## Option D: The Decoupled Ledger
We adopt "Option D", formally decoupling the execution DAG from the visual ledger.

1. **Path as a Visual Epic:** The `Path` issue is explicitly demoted to an Operator-facing visual "Folder/Epic". It has no execution meaning. 
2. **Unified DAG Leaves:** The Next-Best-Action evaluator will operate strictly on the leaf nodes (Harmonize/Plan/Act/Reflect), traversing dependencies via `[Depends: XXXX]`.
3. **Dark Substrate Garbage Collection:** We will introduce an auto-checking mechanism. When ANY node completes, the system will look up its parent Path (via GitHub API search `"{node_id} in:body"` or similar, or by tracking `active_path` in frontier) and update the Meta-Index to `[x] #{node_id}`.
4. **Autonomous Path Closure:** When `nba.evaluate()` runs during the terminal `Reflect` node's completion, it will see a fully checked-off Meta-Index, return `path_switching`, and automatically invoke `gh issue close <path_id>`, sweeping away the Zombie Path.

## Implementation Plan (Node 2230)
1. Add a utility in `drivers/github_client.py` or `drivers/gh_graph_skill.py` to toggle a specific issue ID's checkbox in a parent issue's body.
2. Inject this utility into `kernel/node_lifecycle.py` during `complete_active_node` (or `reflect`), so that when a node completes, it autonomously checks itself off in its parent Path's Meta-Index.
3. Enhance the Tier-2 sync script (`daemon_node.py`) to optionally sweep and close orphaned Path containers where all children are already closed (a one-time hygiene sweep for existing zombies).
