# WHAT-1923: Implement Two-Tier Backlog Abstraction with CSI Guards

## 1. Intent
To resolve the SG-0001 (Backlog Dynamics) goal, we will introduce a **Two-Tier Backlog Abstraction**. This enables the `NBADaemon` to evaluate both local WIP paths (Tier 1) and global repository issues (Tier 2) without hanging during offline modes or dropping critical issues from visibility. To prevent state collisions and drift, we will enforce four core invariants using **Cybernetic Steering Invariants (CSI Guards)**—traceback-driven deterministic mechanisms that actively steer the generative engine.

## 2. Invariants & CSI Guards

### 2.1 SSOT Asymmetry Guard
* **Tier 1 (Local Frontier)** is authoritative Bottom-Up.
* **Tier 2 (Global Backlog)** is authoritative Top-Down.
* **CSI Guard**: If the system detects a manual local edit to the projected `artifacts/global_backlog.yml`, it must physically abort the sync loop and throw an explicit error string: `[CYBERNETIC STEERING VECTOR] Global Backlog projection is read-only. Do not edit artifacts/global_backlog.yml manually. Use bin/backlog to mutate global issues.`

### 2.2 Mutually Exclusive Residence Guard
* An issue cannot exist in `artifacts/frontier_state.md` (Active) and `artifacts/global_backlog.yml` (Pending) simultaneously.
* **CSI Guard**: The `plan-start` phase must deterministically purge the acquired Node ID from `artifacts/global_backlog.yml`. If the NBA Scorer detects the same issue ID in both files, it crashes and throws: `[CYBERNETIC STEERING VECTOR] Mutually Exclusive Residence Violation: Issue X is active but still exists in the global backlog cache. Purge it from global_backlog.yml.`

### 2.3 Graceful Offline Determinism Guard
* The `NBADaemon.evaluate()` function must not swallow "Global backlog empty" when 17 issues exist remotely, and it must not crash if the network is down.
* **Mechanics**: In `local_mode=True`, if Tier 1 is empty, the daemon dynamically reads `artifacts/global_backlog.yml` to populate Tier 2 recommendations.

### 2.4 Sluice Gate Triggering Guard
* Any local creation of a backlog item via `bin/backlog new` must immediately push the state over the wall to GitHub.
* **Mechanics**: Append an explicit call to `git push` or the remote issue creation API in `daemon_backlog.py` rather than allowing it to rest un-pushed.

## 3. Implementation Steps
1. Create `artifacts/global_backlog.yml` as the target schema for Tier 2 projection.
2. Modify `kernel/daemon_nba.py` so `local_mode=True` loads Tier 2 recommendations from `global_backlog.yml` when the local frontier is empty.
3. Inject the Mutually Exclusive Residence check into `kernel/daemon_nba.py`.
4. Modify `bin/node sync` (`kernel/node_lifecycle.py` and `kernel/daemon_node.py`) to periodically dump the result of `github_client.list_issues_by_label("backlog")` into `artifacts/global_backlog.yml` when `remote_mode=True`.
5. Update `test_daemon_nba.py` to assert the CSI Guard tracebacks.
