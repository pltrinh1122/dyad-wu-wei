# WHAT-2205: Concurrent Factory Floor WIP-N=1 Bypassing

## Concept
The Substrate's WIP-N=1 invariant historically enforced a global lock on all planning operations if *any* Pull Request was open. While this prevented duplicate state generation, it directly violated the Concurrent Factory Floor Pattern by artificially restricting the autonomous fan-out architecture. The Agent must be capable of simultaneously dispatching and tracking multiple independent paths while other PRs wait for Operator ratification.

## Technical Requirements
- `kernel/node_lifecycle.py` must filter the `open_prs` list to determine if an active PR explicitly conflicts with the exact node being planned.
- The conflict resolution relies on parsing the `headRefName` of the PR to extract the issue ID (e.g., `node/2205-`).
- If an exact ID conflict exists, the WIP-N=1 invariant MUST block the `plan-start` operation to prevent duplicate execution loops.
- If no exact ID conflict exists, the invariant MUST silently bypass the block, unlocking the engine to dispatch the next node.

## Test Conditions
- Positive Test: `node_lifecycle.py` bypasses `sys.exit` if an unrelated PR is open.
- Negative Test: `node_lifecycle.py` successfully triggers `sys.exit` if an explicitly related PR is open.
