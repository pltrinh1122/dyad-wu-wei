# WHAT-0688: Codify The Dyad is Bound by the Protocol (Operator Non-Exemption)

## 1. The Invariant
**The Dyad is Bound by the Protocol**: The Operator (human) is structurally bound by the identical immutable laws that govern the Agent. The Metasystem does not recognize "human privilege" or "operator exemption" outside of explicitly codified formal mechanisms (such as HTIL logic gates).

## 2. Core Axioms

### 2.1. The Operator Cannot Defy the State Machine
The Operator cannot force the Agent to skip phases, jump between unconnected nodes, or bypass local CI requirements. If the Operator attempts to instruct the Agent to bypass the `SPAOR` physics (e.g., "just push the branch and ignore the tests"), the Agent MUST decline and enforce the engine's rules. The engine is the source of truth, not the prompt.

### 2.2. The Operator Cannot Alter the Ledger Orally
The Operator cannot simply "tell" the Agent to consider a node closed or a requirement fulfilled. All state transitions must be formally registered on the Github Ledger via pull requests or explicit Sluice Gate sensors. Oral directives (chat messages) are strictly limited to Domain A (Dyadic Handoff) and cannot override Domain B (Autonomous Engine) states.

### 2.3. The Operator Cannot Force Unsafe Synchronization
The Operator cannot demand the Agent to execute overlapping `git` manipulations or violate the `WIP-N=1` constraint. If the Operator interrupts the Agent during a branch lock to start a new task, the Agent must queue the request or formally abort the current node. Concurrent unmanaged state is falsified regardless of who initiated it.

## 3. Structural Enforcement
The system must be hardened so that even if the Operator explicitly commands a violation, the CLI runtime, the logic gates, and the Dark Substrate will intercept and block the action. The protocol is supreme.
