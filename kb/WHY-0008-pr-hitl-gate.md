# WHY-0008: The Pull Request HITL Gate

**Date:** 2026-05-16
**Status:** Accepted

## Context
During the repository bootstrapping phase, the Meta-Orchestrator operated on a "direct-to-main" integration model. The `drivers/flow_state_manager.py` skill would automatically commit and push codebase mutations directly to `main` at the conclusion of every Node. As we transition into Active Operations, direct-to-main pushes pose an unacceptable risk of integrating unverified, hallucinated code.

## Decision
We establish the **Branch & Pull Request (PR) HITL Gate** as the mandatory integration pathway for all future operations, grandfathering in all previous direct-to-main commits.

## The Standards
To support this gate, the following strict invariants are mathematically enforced by the `drivers/` pillar:

1. **Branch Naming Standardization:** All branches generated by the Agent must rigidly adhere to the `node/<id>-<kebab-case>` regex (e.g., `node/16-pr-hitl-gate`). If the Agent attempts to reflect a node with an arbitrary branch name, the orchestrator skill will crash.
2. **The Hard HITL Block:** The Agent's `reflect_node` skill now pushes the branch and automatically opens a Pull Request against `main`. Crucially, this physically paralyzes the Agent from advancing the topology on `main` until the Operator reviews, approves, and merges the PR.
3. **Local Branch Hygiene:** Because the Agent will now iterate across many local branches, the SPAO "Sense" phase now executes `sync_and_clean_node()`, which pulls `main`, prunes remote-tracking references, and automatically deletes local branches that have been safely merged.
