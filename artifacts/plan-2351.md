# Technical Design Plan: Relocate Autonomous Path Execution to DYAD.md
**Node ID:** 2351
**Context:** Relocate Swarm Fan-Out mechanics from `GEMINI.md` to `DYAD.md` to make them agent-agnostic.

## 1. Modifications to `GEMINI.md`
**Action:** Remove the `## Antigravity-Specific: Autonomous Path Execution (Wu-wei)` section in its entirety.

**Lines to delete:**
```markdown
## Antigravity-Specific: Autonomous Path Execution (Wu-wei)
- Administrative Node NBA: Execute `./bin/node plan-start <ID>`. **Exception:** For `[BUG]` paths, the entire Path (including Harmonize and Plan nodes) MUST be dispatched to a sub-agent to bypass the Strategist's cognitive bottleneck.
- Execution Node (Act) NBA: Dispatch by invoking the appropriate subagent via the `invoke_subagent` tool.
- Concurrent Factory Floor Dispatch: Frontier MUST dispatch `Act` nodes (and full `[BUG]` paths) immediately to sub-agents via `invoke_subagent` and then immediately `plan-start` the next available Path in the backlog without halting or waiting for the sub-agents to complete.
```

## 2. Modifications to `DYAD.md`
**Action:** Append a new universal section detailing Sub-Agent Swarm Fan-Out Mechanics. This will act as the engine schema for concurrent fan-out, independent of the agent persona.

**Content to append:**
```markdown
## 7. Sub-Agent Swarm Fan-Out Mechanics
To support concurrent execution and bypass single-agent cognitive bottlenecks, the Agent MUST implement the following push-model sub-agent orchestration protocols:
- **Administrative Node NBA**: Execute `./bin/node plan-start <ID>`. **Exception:** For `[BUG]` paths, the entire Path (including Harmonize and Plan nodes) MUST be dispatched to a sub-agent to prevent clogging the primary orchestration loop.
- **Execution Node (Act) NBA**: Dispatch by invoking the appropriate sub-agent via the `invoke_subagent` tool.
- **Concurrent Factory Floor Dispatch**: The Agent MUST dispatch `Act` nodes (and full `[BUG]` paths) immediately to sub-agents via `invoke_subagent` and then immediately execute `plan-start` for the next available prioritized Path in the backlog without halting or waiting for the dispatched sub-agents to complete.
```

## 3. Rationale
By moving these mechanics from the Frontier-specific HAL (`GEMINI.md`) into the global engine schema (`DYAD.md`), we fulfill the Portability Axiom. This allows any instantiated agent persona (not just the Frontier Wu-wei Dyad) to leverage concurrent factory floor dispatching natively.
