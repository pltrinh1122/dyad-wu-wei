# Plan: Falsify PR and Node Conflation

## Problem Statement
The execution engine occasionally conflates Pull Request IDs with Node IDs because both share the same numerical sequence in GitHub. This causes `plan-start` and `sync` invariants (like `WIP-N=1`) to fail when it misidentifies an active PR as an active Node, throwing `Cannot plan node #Y because there are open pull requests: [X]`.

## Proposed Solution (Implemented in Node 1606)
To systematically falsify this conflation, the system's `WIP-N=1` check in `kernel/node_lifecycle.py` needs to explicitly read the branch name (`headRefName`) associated with the PR, rather than just the integer ID.

By emitting `PR #{pr_id} (branch: {branch_name})`, the system guarantees that the logical node ID can be independently verified against the Git branch naming convention (`node/{node_id}-...`), cleanly decoupling the version control branch abstraction from the Node ID primitive.

## Secondary Fix (Discovered in Node 1603)
During the harmonization of this path, it was discovered that `daemon_nba.py` could fail entirely due to a GitHub CLI deprecation warning on `stderr` exiting with `1`. This will be suppressed by hardening `github_client.py` to accept non-zero exit codes when valid JSON is returned on `stdout`.

## Execution Steps
1. Modify `kernel/node_lifecycle.py` to extract `headRefName` in the `WIP-N=1` invariant check.
2. Update the `[🚫 BLOCKED]` failure message to explicitly print the branch name alongside the PR ID.
3. Harden `drivers/github_client.py`'s `_run_gh` to handle GraphQL deprecation warnings gracefully.
4. Clean the global backlog of any legacy mock issues.
