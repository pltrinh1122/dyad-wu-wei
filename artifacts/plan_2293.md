# Plan: Gut Local Lock Ledger and Implement API-Driven kernel_daemon for Swarm Fan-Out

## 1. Objective
Excise the global `frontier_state` locking mechanisms from the core Engine to eliminate `WIP-N=1` Git push collisions and enable true concurrent sub-agent swarm fan-out. The true execution lock will shift entirely to the GitHub Issue `status: in-progress` label (Decoupled Geometry).

## 2. Component Refactoring

### A. `kernel/node_lifecycle.py`
- Remove all calls to `agent_frontier.set_active_node` in `plan_start`, `checkout`, and `reflect`.
- The act of locking a node will strictly rely on `set_status(issue_id, "status: in-progress")`. The `[📋 PLAN] Plan-Start Executed` log will no longer mention updating the frontier.

### B. `kernel/daemon_strategic.py`
- Remove `_verify_persona` completely. The validation logic was inherently flawed because `status: in-progress` alone guarantees that another agent will not select the node as a Next-Best-Action from the `status: todo` queue. 
- Retain the `verify_node_transition_allowed` parent-path integrity check, but strip any code that parses `artifacts/frontier_state.yml` to check who holds the lock.

### C. `kernel/agent_frontier.py`
- Deprecate or remove `set_active_node` since no system components will invoke it.

### D. `bin/status` and `skills/frontier_editor.py`
- `skills/frontier_editor.py` will no longer append the `Active Agents Matrix` and `Current Active Node` to `artifacts/frontier_state.md`.
- `bin/status` will no longer parse `artifacts/frontier_state.yml` to display agent locks. Instead, the `bin/status` command will rely on the `gh issue list` to display active `status: in-progress` nodes (the Ad-Hoc Ledger).

## 3. Test Remediation
- We must remediate any tests in `tests/test_node_lifecycle.py` and `tests/test_daemon_strategic.py` that explicitly verify `set_active_node` or `_verify_persona` behavior.

## 4. Work Order
1. Act Node 2294 will execute the refactoring of `daemon_strategic.py` and `node_lifecycle.py`.
2. Ensure test coverage remains green.
3. Remove physical lock matrix from `frontier_editor.py`.
