# Plan: [BUG] Intake: System Crash in reflect

## Goal
To implement a robust fix for the system crash in the `reflect` command.

## Analysis
The root cause was identified from the retro artifact of Node 2270: when the `reflect` command is invoked before creating a local worktree via `checkout`, the `reflect` subcommand attempts to determine the Git status using `git status --porcelain` with `cwd=worktree_dir`. Since the worktree hasn't been created yet, `subprocess.run` raises a `FileNotFoundError`, crashing the daemon and risking a system seizure.

## Action Plan
1. **Target**: Modify `kernel/node_lifecycle.py` inside the `reflect` method.
2. **Implementation**: 
   Before invoking `git_client.status_porcelain`, check if the calculated `worktree_dir` actually exists.
   If it does not exist, immediately raise a controlled `sys.exit("[🚫 BLOCKED] Reflection Blocked: The worktree directory does not exist. You must run './bin/node checkout <node_id> <branch_name>' before reflecting.")`.
3. **Validation**: Run the automated test suite (`pytest tests/`) to ensure no existing tests are broken and invariants are preserved.

## Constraints
- The Agent must maintain True Dormancy and the frictionless autonomous substrate.
- Ensure the fix gracefully converts a user error (missing checkout) into a controlled blocked state instead of a stack trace crash.
