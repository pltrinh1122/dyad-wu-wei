# Plan: Elevate Path Status

## 1. Goal
Automatically query the parent Path and elevate its label from `status: todo` to `status: in-progress` when a child node is locked (either via `plan-start` or `checkout`).

## 2. Technical Design

### Injection Points
The easiest and most logical integration point is to modify `kernel/daemon_node.py` specifically intercepting `plan_start_node` and `checkout_node`.

We will implement a new helper function `_elevate_parent_path_status(issue_id: str)`:
```python
def _elevate_parent_path_status(issue_id: str) -> None:
    """Automatically query the parent Path and elevate its label from 'status: clarify' to 'status: execute'."""
    try:
        from kernel import daemon_strategic
        from kernel.node_lifecycle import BaseNode, load_node_status_config
        parent_path_id = daemon_strategic.find_parent_path_id(str(issue_id))
        if parent_path_id and str(parent_path_id) != str(issue_id):
            path_node = BaseNode(parent_path_id)
            path_labels = path_node.gh_labels
            clarify_label = load_node_status_config().get("clarify", "status: clarify")
            if clarify_label in path_labels:
                path_node.set_status("execute")
                print(f"Elevated parent Path #{parent_path_id} status to in-progress.")
    except Exception as e:
        print(f"Warning: Failed to elevate parent path status: {e}")
```

We will then modify `plan_start_node` and `checkout_node` to call `_elevate_parent_path_status(issue_id)` right after the `node.plan_start()` or `node.checkout()` methods are successfully invoked. This guarantees that whenever a Node transitions to `in_progress`, its parent Path will also transition to `in_progress` if it was previously in `todo`.

### Justification
- Decoupled from `node_lifecycle.py` transaction internals to avoid side-effects or locking deadlocks.
- Fails gracefully by catching all exceptions, ensuring that network errors or unexpected conditions do not block the node's checkout or plan-start workflow.
- Follows the DRY principle by extracting the code into a shared `_elevate_parent_path_status` helper.

## 3. Implementation Plan
1. Edit `kernel/daemon_node.py` to insert `_elevate_parent_path_status`.
2. Add the call to `_elevate_parent_path_status(issue_id)` inside `plan_start_node`.
3. Add the call to `_elevate_parent_path_status(issue_id)` inside `checkout_node`.
4. Run `pytest tests/` to ensure no unit tests are broken.
