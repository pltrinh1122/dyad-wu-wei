# Plan - Path: The Sub-Agent Gateway Controller (Ignition)

## 1. Goal
To implement the Gateway Controller CLI command (`bin/node dispatch`) within `kernel/daemon_node.py` that safely transitions a locked Node from the kernel_daemon's domain into a sub-agent's execution domain, officially recording the context shift in the concurrent lock ledger.

## 2. Approach
- **Command:** Add `dispatch` parser to `kernel/daemon_node.py`.
- **Arguments:**
  - `issue_id`: The ID of the node to dispatch.
  - `persona`: The target sub-agent persona (e.g. `research`, `test`).
- **Execution Flow:**
  1. Validate the `issue_id` exists and is currently locked by the active kernel_daemon.
  2. Read `artifacts/frontier_state.yml` to confirm the lock exists.
  3. Re-bind the lock: Update `active_agents` in `frontier_state.yml` so that `issue_id` is now mapped to `persona`, and the current kernel_daemon's lock is released.
  4. Yield Execution: The kernel_daemon logs the handoff and strictly terminates execution, ensuring True Dormancy.

## 3. Structural Modifications
- `kernel/daemon_node.py`:
  - Add `parser_dispatch` with `issue_id` and `persona` arguments.
  - Create `sync_dispatch_node(issue_id, persona)` function.
- `kernel/agent_frontier.py`:
  - Verify and expose state-binding functions if needed (we can utilize existing `set_frontier_active_node` and `set_frontier_active_path` functions for the target persona while clearing the current persona).

## 4. Test Strategy
- Create test `tests/test_gateway_controller.py` or append to `tests/test_daemon_node.py`.
- Mock the concurrent ledger and assert that `dispatch` correctly shifts the persona lock and clears the kernel_daemon lock.
- Ensure the Gateway yields `0` (success) while enforcing dormancy.
