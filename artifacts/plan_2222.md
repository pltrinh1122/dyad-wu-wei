# WHAT-2220: System Crash StateCorruptionError Graceful Handling Architecture

## Context
The SPAO system utilizes a unified exception catching mechanism in `daemon_node.py` to intercept unhandled exceptions and autonomously file bug reports (Intake Issues). However, the `StateCorruptionError` raised by `agent_frontier.load_state` when a frontier state checksum mismatch occurs is an intentional validation gate. When a user manually edits `artifacts/frontier_state.yml`, the system intentionally detects the corruption to force the user to rehash. Because `StateCorruptionError` is not caught by the intentional exception tuple in `daemon_node.py`, it falls through to the global error handler, resulting in a false-positive system crash report, such as "[BUG] Intake: System Crash in sync".

## Design Decision
Validation blocks are intentional mechanism rejections, not unexpected system failures. They must not trigger autonomous bug reporting.

1. **Clean Exit for Validation:** `StateCorruptionError` must be treated identically to `ValidationError` and other intentional gating exceptions.
2. **Global Error Handler Update:** The exception handler in `daemon_node.py` must catch `StateCorruptionError` and gracefully exit with `[🚫 BLOCKED]` instead of proceeding to the crash reporter.

## Implementation Strategy
- In `kernel/daemon_node.py`, import `StateCorruptionError` from `kernel.agent_frontier`.
- Update the `except (ValidationError, StateDissonanceError, ReflectionBlockedError) as ve:` block in `main()` to also catch `StateCorruptionError`.
