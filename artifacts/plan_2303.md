# Plan: Decouple Prompt Channel to GitHub API and Instantiate Singular Staging Area

## 1. Objective
Achieve true Decoupled Geometry by fully excising the physical `artifacts/prompt_backlog.yml` file, migrating all unstructured Operator prompts and intents to a unified "Singular Staging Area" backed by GitHub Issues tagged with the `staging` label.

## 2. Component Refactoring

### A. Excision of Physical Backlog
- Delete the file `artifacts/prompt_backlog.yml` from the repository.

### B. `kernel/daemon_status.py`
- Refactor the `get_prompt_backlog_size()` function. It must no longer parse the physical yaml file.
- Instead, it must dynamically query the GitHub API (e.g., using `drivers.github_client` or `gh issue list --label "staging"`) to return the count of open issues bearing the `staging` label.

### C. `kernel/node_lifecycle.py`
- Modify the `plan_start` HTIL gate. If `get_prompt_backlog_size() > 0`, it must throw a strongly-typed `StagingAreaBlockedError`.
- The error message should read: `Pending items in Singular Staging Area. You must harmonize issues labeled 'staging' before acquiring a new Node lock.`

### D. `bin/prompt`
- Rewrite `bin/prompt` to be a pure GitHub API wrapper.
- `bin/prompt queue <msg>` should invoke `gh issue create --title "Prompt: <msg>" --label "staging"`.
- `bin/prompt process` should invoke `gh issue list --label "staging"` to display the backlog to the Operator.

### E. Node Status Decoupling
- In `kernel/daemon_backlog.py` (or related generators), when creating formal DAG nodes (Harmonize, Plan, Act, Reflect), ensure they do NOT use the `status: todo` label to avoid cognitive overlap. They should be generated strictly with the `backlog` label, or transitioning legacy `status: todo` assignments to `status: backlog`.
- In `kernel/daemon_node.py` (the Orphaned WIP CSI Guard), when downgrading a seized node, downgrade it to `backlog` rather than `status: todo`.
