# Node 2104 Plan: Concurrent DAG Evaluation (The Scoring Alg)

## Goal
Evolve the Next-Best-Action (NBA) logic in `kernel/daemon_nba.py` to explicitly filter out nodes that are currently locked by executing workers (personas), ensuring no double-dispatching occurs.

## Context
As the kernel_daemon dispatches work to multiple sub-agents (e.g., `agent-sg5`, `agent-ziran`), `artifacts/frontier_state.yml` tracks each agent's `current_active_node`. The NBA engine must prevent these locked nodes from being recommended in the `path_continuation` or `path_switching` tiers.

## Execution Strategy
1. **Identify Locked Nodes**: Read `artifacts/frontier_state.yml` (using `agent_frontier.load_state`) to collect all `current_active_node` values from the `active_agents` dictionary. Extract their numerical issue IDs into a `locked_node_ids` set.
2. **Filter Path Continuation Tier**: When processing child candidates for the active path (lines 48-95) or from GitHub issues (lines 99-111), exclude any node whose ID is in `locked_node_ids`.
3. **Filter Global Backlog Tier**: When processing the global backlog items (lines 116-214), exclude any node whose ID is in `locked_node_ids`.
4. **Validation**: Update `tests/test_daemon_nba.py` to mock `artifacts/frontier_state.yml` with active sub-agents and assert that those locked nodes are NOT returned in the NBA list.
