# Plan - Path: Concurrent Lock Ledger Materialization (Internal State)

## 1. Context & Intent
As identified in Node #2091, the system's execution lock has evolved from a monolithic `artifacts/frontier_state/lock.json` into a concurrent ledger located in `artifacts/frontier_state.yml` under the `active_agents` key. However, residual verification logic—specifically the Orphaned WIP CSI Guard in `kernel/daemon_node.py`—still relies on the deprecated monolithic lock file. This causes valid concurrent nodes to be incorrectly downgraded. This plan implements the resolution to support true multi-agent execution.

## 2. Technical Design

### A. `kernel/agent_frontier.py`
- **Helper Addition:** Implemented `get_all_active_locked_issue_ids(filepath)` which aggregates all issue IDs embedded in `current_active_node` and `current_active_path` strings across all agents listed in the `active_agents` dictionary. It acts as the definitive source of truth for all valid held locks.

### B. `kernel/daemon_node.py`
- **CSI Guard Refactor:** Modified the `Orphaned WIP CSI Guard` to invoke `get_all_active_locked_issue_ids()`. The guard will now evaluate any issue currently labeled `status: in-progress` against the aggregated set of legitimate concurrent locks. If an issue is not held by *any* agent, it will correctly be downgraded to `status: todo`.
- **Cleanup:** Eradicated the explicit file-read logic for `artifacts/frontier_state/lock.json`.

## 3. Verification
- **Test Suite:** Execute `bin/run-tests` to ensure no regressions in lexical invariants or state parsing.
- **Runtime:** Sub-agents spawning or concurrent execution of nodes should no longer randomly trigger the CSI Guard downgrades during `bin/node sync`.
